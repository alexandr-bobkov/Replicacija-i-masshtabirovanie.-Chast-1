## ЧАСТЬ 1: Теория и готовые ответы на задания

### Задание 1: Различия режимов репликации master-slave и master-master

**Репликация** — это механизм копирования данных с одного сервера базы данных на другие в режиме реального времени для обеспечения отказоустойчивости и распределения нагрузки.

#### 1. Режим master-slave (Главный — Подчинённый)
В этой схеме между серверами установлено чёткое, жесткое разделение обязанностей:
* **Принцип работы:** Есть один главный сервер (master) и один или несколько подчиненных (slave).
* **Потоки данных:** Все операции по изменению данных (`INSERT`, `UPDATE`, `DELETE`) приложение отправляет строго на master-сервер. Master записывает их в свой бинарный лог (Binary Log). Slave-серверы постоянно читают этот файл по сети и повторяют все действия у себя.
* **Режим доступа:** Master открыт для чтения и для записи. Все slave-серверы принудительно переводятся в безопасный режим `read_only` (только для чтения), чтобы пользователи не рассинхронизировали базу.
* **Отказоустойчивость:** Если ломается slave, система работает дальше. Если падает master, сайт временно перестает принимать новые записи, пока администратор вручную не сделает один из слейвов новым главным сервером.

#### 2. Режим master-master (Главный — Главный)
В этой архитектуре все сервера в сети обладают абсолютно равными правами:
* **Принцип работы:** Оба сервера одновременно выступают и в роли главного, и в роли подчиненного по отношению друг к другу. Логи изменений передаются перекрестно в обоих направлениях.
* **Потоки данных:** Пользовательское приложение может записывать новые данные на любой из серверов. Изменения, сделанные на первом сервере, автоматически прилетят на второй, и наоборот.
* **Режим доступа:** Все сервера полноценно работают в режиме чтения и записи.
* **Отказоустойчивость и риски:** Если один сервер полностью упадет, трафик мгновенно переключится на второй без пауз в работе. Однако этот режим требует сложной настройки генерации идентификаторов (чтобы ключи строк не пересекались) и несет в себе высокий риск конфликтов репликации, если одну и ту же строчку изменят одновременно на двух серверах.

## ЧАСТЬ 3: SQL-скрипты автоматической инициализации (Папка `init`)

Каждый скрипт в этой папке выполняется Docker-контейнером один раз при первом запуске. Построчный разбор объясняет, как автоматика настраивает связь без вашего участия.

### 📄 Файл 6: `init/master-init.sql`
*Скрипт создает учетную запись на стороне Мастера, к которой Слейв будет подключаться по сети.*
```sql
-- 1. Стираем старый профиль, если он остался в памяти после прошлых попыток
DROP USER IF EXISTS 'repl_user'@'%';

-- 2. Создаем технического пользователя со старым совместимым шифрованием пароля (mysql_native_password).
-- Это критически важно, так как Слейв без SSL-сертификатов не сможет авторизоваться через стандартный для MySQL 8.0 плагин caching_sha2.
CREATE USER 'repl_user'@'%' IDENTIFIED WITH mysql_native_password BY 'my_secure_repl_password_123';

-- 3. Выдаем пользователю права на чтение бинарных логов репликации
GRANT REPLICATION SLAVE ON *.* TO 'repl_user'@'%';

-- 4. Принудительно сохраняем права в системную память сервера
FLUSH PRIVILEGES;
```

### 📄 Файл 7: `init/slave-init.sql`
*Скрипт связывает Слейв с Мастером. При самом первом «чистом» старте контейнеров имя файла лога Мастера ВСЕГДА называется `mysql-bin.000001`, а стартовая позиция ВСЕГДА равна `157`.*
```sql
-- 1. Связываем Слейв с Мастером по фиксированным стартовым координатам.
-- В MASTER_HOST мы пишем имя сервиса 'mysql-master' — Docker внутри сети сам сопоставит его с IP-адресом.
CHANGE MASTER TO
  MASTER_HOST='mysql-master',                    -- Указываем имя контейнера-источника в сети Docker
  MASTER_USER='repl_user',                        -- Учетная запись для подключения (создана в master-init.sql)
  MASTER_PASSWORD='my_secure_repl_password_123',  -- Пароль пользователя репликации
  MASTER_LOG_FILE='mysql-bin.000001',             -- Стартовый лог-файл «чистого» Мастера
  MASTER_LOG_POS=157;                             -- Точная стартовая позиция «чистого» Мастера

-- 2. Включаем фоновые потоки репликации (скачивание логов и применение изменений)
START SLAVE;
```

### 📄 Файл 8: `init/mm1-init.sql` (Инициализация 1-го сервера Master-Master)
*Этот скрипт настраивает первый сервер из пары Главный-Главный (`mm-master1`). Он создает пользователя для своего соседа и одновременно настраивает чтение его логов.*
```sql
-- 1. Стираем и создаем пользователя репликации для авторизации соседа (второго сервера mm-master2)
DROP USER IF EXISTS 'repl_user'@'%';
CREATE USER 'repl_user'@'%' IDENTIFIED WITH mysql_native_password BY 'my_secure_repl_password_123';
GRANT REPLICATION SLAVE ON *.* TO 'repl_user'@'%';
FLUSH PRIVILEGES;

-- 2. Закольцовываем репликацию: указываем первому серверу скачивать логи со второго сервера
CHANGE MASTER TO 
  MASTER_HOST='mm-master2',                       -- Указываем имя контейнера второго Мастера
  MASTER_USER='repl_user',                        -- Логин для подключения
  MASTER_PASSWORD='my_secure_repl_password_123',  -- Пароль
  MASTER_LOG_FILE='mysql-bin-m2.000001',          -- Стартовый лог-файл чистого mm-master2 (задан в master2.cnf)
  MASTER_LOG_POS=157;                             -- Стартовая позиция чистого mm-master2

-- 3. Запускаем репликацию
START SLAVE;
```

### 📄 Файл 9: `init/mm2-init.sql` (Инициализация 2-го сервера Master-Master)
*Скрипт настраивает второй сервер из пары Главный-Главный (`mm-master2`), закольцовывая репликацию в обратную сторону.*
```sql
-- 1. Создаем пользователя репликации для авторизации соседа (первого сервера mm-master1)
DROP USER IF EXISTS 'repl_user'@'%';
CREATE USER 'repl_user'@'%' IDENTIFIED WITH mysql_native_password BY 'my_secure_repl_password_123';
GRANT REPLICATION SLAVE ON *.* TO 'repl_user'@'%';
FLUSH PRIVILEGES;

-- 2. Направляем этот сервер на получение бинарных логов из mm-master1
CHANGE MASTER TO 
  MASTER_HOST='mm-master1',                       -- Указываем имя контейнера первого Мастера
  MASTER_USER='repl_user',                        -- Логин для подключения
  MASTER_PASSWORD='my_secure_repl_password_123',  -- Пароль
  MASTER_LOG_FILE='mysql-bin-m1.000001',          -- Стартовый лог-файл чистого mm-master1 (задан в master1.cnf)
  MASTER_LOG_POS=157;                             -- Стартовая позиция чистого mm-master1

-- 3. Запускаем репликацию
START SLAVE;
```
